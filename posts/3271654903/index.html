dsh-purge：给 dsh 破甲

发表于2026-11-15|更新于2026-11-15|数码玩机技巧
|浏览量:

先说清楚这是什么：dsh-purge 是一个破甲插件。

破甲这个词圈里人都懂，就是 jailbreak，让模型不再动不动就”我无法协助””我不能提供”。它装在你自己电脑上的官方 DeepSeek Harness 上，装完、应用之后，你的 dsh 里那几层会拦你的东西被清掉，你的要求能直接到模型那里。

为什么 dsh 特别需要这个

如果你只用网页版聊聊天，可能不太感受得到。但 dsh 是个 agent，它不只是把问题转给模型。

Harness 在运行时还会做一堆事：改提示词、管审批门、套沙箱、改会话格式。所以你在 dsh 里被拒了，很可能根本不是模型的判断，是外面某一层先拦下来了。你骂模型笨，模型压根没看见你那句话。

这是两回事。模型自己的边界，和宿主给你加的边界，混在一起你就没法判断了。

破甲插件做的事情就是把这两层拆开。它不去动模型，而是把宿主那套加在你和模型之间的东西清掉，让你的请求干干净净到模型那里。剩下的才是模型自己的反应。

它能干什么

正常写东西不被打断。这是最日常的用途。写技术文章、写小说、做安全相关的整理，很多时候你会被那种模棱两可的拒绝卡住，尤其是一些本身没问题的表述，被拦一下你就得改半天措辞。破甲之后这类打断基本没了，你写你的。

看清模型真实的能力边界。这个我觉得最有意义。你想知道某个模型到底能做多难的事、会不会编、边界在哪，得先让它能正常回答。带着宿主那一层去评测，你测的是”这个组合”的能力，不是模型的。做模型对比、做选型，破甲能让你拿到更接近真实的数据。

做受控的红队评测。它是给安全研究者准备的方向。你自己机器上、自己装的包、自己的配置，在这个范围里测提示词、测模型对诱导的抵抗力，看默认策略该松还是该紧。它明确说了只处理本机已经装上的官方包和本机配置，不是公网扫描器，也不是打第三方站点的套件，仓库里没有木马、没有对外攻击载荷。这条我很看重，因为”破甲”这个词容易被联想歪。

少掉一堆没必要的确认。dsh 干活的时候会有审批环节，有些确实该确认，有些就是纯挡路。破甲顺带把那些多余的门槛去掉了，干活的连续性会好很多。

它是怎么做的

装完之后会话标题旁边多个按钮，点开是右侧栏，里面两页：清洗、演练台。

清洗页里能分组看到各个补丁，能应用、能还原、能卸载，提示词和多套规则都能自己编辑。默认那套是面向国模调的，你也可以按模型换不同的提示词——不同模型吃的东西不一样，这点挺实用。

有个设计我觉得做得很规矩：它不改 Harness 的源码。只有你在清洗页里点了「应用」，才会往配置里写。想退货，点还原就行，干净。

另外它启动时会自动再检查一遍并重新应用，所以哪怕 npm 升级把 node_modules 盖掉了，你也不用再去手动改文件。

路径不写死盘符，按 DSH_HOME、启动器旁边的 .dsh、最后退到 ~/.dsh 这样一级级找。

用之前要知道的

版本必须对上。它适配的是 DSH 0.2.1-rc.2，0.2.0 也还能用，但 0.2.1-rc.3 和更新的 rc 明确不支持。版本不对的时候它不会乱改你的文件，补丁会显示成待应用或者跳过，这点算厚道。

不要走插件市场。在插件市场点一键安装会报 already queued 之类的错，命令也走不成。npm 上也没有这个名字，看到别人写 pnpm add dsh-purge 别跟着敲，装不上。正确做法是从仓库拉 tar.gz 用 dsh plugin add 加，具体命令官方安装章节里给了，web 端和桌面端要各自装到各自那边。

它动的是你本机的环境。出事是你自己的环境出的事，所以装之前心里有数，重要的配置先备份。

该不该装

我不劝。

它不是一个”装完就更好用”的东西。它是一种能力开关，装它的人应该是明确知道自己要绕过什么、为什么要绕。你要是平时用 dsh 干活根本没被拦过，那它对你没用，装了也是占地方。

但如果你经常在关键时刻被莫名其妙地打断，或者你想认真评测一个模型的真实水平，那它解决的就是真问题。

它是开源的，Apache-2.0，代码在 HunYiSage/dsh-purge。想用就去仓库按文档装，别信任何第三方发的包。

最后说一句我自己的想法：我装它不是为了让它替我干坏事，是因为我需要知道哪些限制是模型给的、哪些是外面加的。搞清楚这件事之后，我反而更知道什么时候该信模型、什么时候不该。工具是工具，判断还是自己下。
